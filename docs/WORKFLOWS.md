# GitHub Actions

Since cutover (Sun 22 Nov 2026, D-239/D-240) the hourly workflows run on the same timers as the old repository. Each still does nothing unless its `*_ENABLED` variable is `true`. Only CI and the full test suite run on a pull request.

GitHub skips some scheduled runs. The Cloudflare Worker (`ops/cloudflare/kg-dispatch-worker.js`) starts the missed ones.

To stop everything: set every `*_ENABLED` variable to `false`. Runs still start, but their jobs are skipped.

CI (`.github/workflows/ci.yml`) runs on a pull request. It installs from the lockfile with scripts off, lints, runs the tests (`npm test`) and audits dependencies. It does not build the five contracts yet: `npm run test:contracts` is not in CI (HANDOFF.md item 2). It cannot write to the repository.

## Turning the website on

1. Settings → Pages → Build and deployment → Source: **GitHub Actions**. Not "Deploy from a branch". A branch deploy would publish the whole repository, including tests.
2. Settings → Secrets and variables → Actions → Variables → New repository variable. Name `KG_ENABLE_PAGES`. Value `true`.
3. Actions → Publish the website → Run workflow, on `main`.

Until step 2, the Run button starts a workflow whose job is skipped.

To turn it off, set `KG_ENABLE_PAGES` to anything other than `true`, or delete the variable.

## Turning the bot on

The bot workflow is `bot.yml`. Its jobs already refuse to run unless:

- you pressed Run workflow, and
- the variable `BOT_ENABLED` is `true`, and
- the run is on `main`.

The operator key belongs in an environment named `bot`, with a deployment branch rule of only `main`. Do not put `OPERATOR_WIF` in a normal repository secret.

A manual run does one tick. The timers are in the table above.

## The other workflows

The contract-test workflows and `games-testnet.yml` are manual (Run workflow only). The hourly ones are in the table above.

## What you should not turn on

- A new or changed `schedule:` without a pull request that also changes `TIMERS` in `tools/ci/lint.mjs`.
- Pages set to "Deploy from a branch".
- `pull_request_target` or a workflow that has `write-all`. CI will fail the policy lint if those appear.
